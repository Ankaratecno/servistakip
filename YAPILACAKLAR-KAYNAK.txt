Sorunun Analizi
Yolcuların gördüğü hız göstergesinde, araç durduğunda (kırmızı ışık vb.) hız 0’a düşüyor ama tekrar hareket ettiğinde güncellenmemesi sorunu GPS gürültü filtresinin çok agresif çalışmasından kaynaklanıyor.

Kök Neden
trip-stats.ts dosyasındaki ingestFix fonksiyonunda şu mantık var:

noiseFloor (gürültü eşiği) çok yüksek: Araç durunca smoothedKmh hızla 0’a yaklaşıyor (EMA ile azaltılıyor). Tekrar hareket ettiğinde ise:
typescript

const noiseFloor = Math.max(8, (fix.accuracy + prev.accuracy) * 0.5);
if (dm < noiseFloor) {
  // Hareket "gürültü" olarak algılanıyor!
  state.smoothedKmh = state.smoothedKmh * (1 - SPEED_SMOOTHING); // 0'a doğru gidiyor
  return { stats, speedKmh: state.smoothedKmh, accepted: false };
}
Minimum noiseFloor 8 metre. Yani araç 8 metreden az hareket ettiyse (düşük hızda ilk birkaç saniye) bu “gürültü” sayılıyor ve hız güncellenmez.

İvme sınırı (MAX_ACCEL_KMH_PER_S = 8): Araç 0 km/s’den aniden 30 km/s’ye çıktığında, smoothedKmh hâlâ 0’a yakınsa, fark/dt oranı ivme sınırını aşıyor ve fix reddediliyor:
typescript

if (Math.abs(segKmh - state.smoothedKmh) / dt > MAX_ACCEL_KMH_PER_S && state.smoothedKmh > 0) {
  return { stats, speedKmh: state.smoothedKmh, accepted: false };
}
MAX_DT = 30 saniye: Eğer kırmızı ışıkta 30 saniyeden fazla durursanız, bir sonraki fix geldiğinde dt > MAX_DT koşulu tetikleniyor ve smoothedKmh sıfırlanıyor, ama yeni hız hesaplanmadan fonksiyondan çıkılıyor.
Çözüm
trip-stats.ts dosyasında şu değişiklikleri yapmanız gerekiyor:

1. noiseFloor minimum değerini düşürün (8 → 4):

typescript

const noiseFloor = Math.max(4, (fix.accuracy + prev.accuracy) * 0.4);
2. MAX_DT süresini artırın (30 → 60):

typescript

const MAX_DT = 60; // kırmızı ışıkta 1 dakikaya kadar bekleme toleransı
3. MAX_DT aşıldığında state’i sıfırladıktan sonra bir sonraki fix’in kabul edilmesini sağlayın:

Mevcut kod:

typescript

if (dt < MIN_DT || dt > MAX_DT) {
  if (dt > MAX_DT) {
    state.lastFix = fix;
    state.smoothedKmh = 0;
    state.fastStreak = 0;
  }
  return { stats, speedKmh: state.smoothedKmh, accepted: false };

Değiştirilmiş hali:

typescript

if (dt < MIN_DT) {
  return { stats, speedKmh: state.smoothedKmh, accepted: false };
}
if (dt > MAX_DT) {
  // Uzun bekleme sonrası: state'i sıfırla, GPS hızı varsa onu göster
  state.lastFix = fix;
  state.fastStreak = 0;
  const gps = fix.gpsSpeedKmh != null && isFinite(fix.gpsSpeedKmh) ? Math.max(0, fix.gpsSpeedKmh) : 0;
  state.smoothedKmh = Math.min(gps, MAX_PLAUSIBLE_KMH);
  return { stats, speedKmh: state.smoothedKmh, accepted: false };
}
4. SPEED_SMOOTHING değerini biraz artırın (0.35 → 0.45):

typescript

const SPEED_SMOOTHING = 0.45; // Daha hızlı tepki
Neden “Sıfırla” Butonu Çözüyor?
Sıfırla butonuna bastığınızda şu çalışıyor:

typescript

filterRef.current = initialFilterState();
setLiveSpeed(0);
Bu, FilterState’i tamamen sıfırlıyor (lastFix = null, smoothedKmh = 0, fastStreak = 0). Böylece bir sonraki GPS fix’i “ilk fix” olarak kabul ediliyor ve filtre kısıtlamaları (ivme kontrolü, gürültü eşiği) uygulanmıyor. İkinci fix geldiğinde ise temiz bir hesaplama yapılıyor.

PeerJS ile Müzik Streaming — Detaylı Cevaplar
1. Kasma / Performans Sorunu
Kısa cevap: Düzgün yapılırsa kasmaz.

WebRTC (PeerJS’in altındaki teknoloji) zaten video konferans için tasarlanmış. Bir audio stream göndermek video göndermekten çok daha hafif:

Veri Türü	Bant Genişliği
Müzik stream (Opus codec)	~96-128 kbps per yolcu
Konum verisi (şu anki)	~1 kbps
Video call	~1-3 Mbps
10 yolcu = ~1.3 Mbps upload. 4G bağlantıda sorun olmaz. WiFi hotspot açarsan daha da rahat.

2. Senkronizasyon (Aynı Anda Aynı Müzik)
WebRTC doğası gereği gerçek zamanlıdır. Gecikme ~200-500ms arası. Yani:

Şoförün duyduğu ile yolcunun duyduğu arasında yarım saniyeden az fark olur

CesiumJS “Ağır” Derken Ne Demek İstiyorum?
CesiumJS, Google Earth benzeri tam 3D dünya görünümü sunan bir kütüphane. “Ağır” derken:

Kriter	MapLibre GL JS	CesiumJS
Dosya boyutu (JS)	~800 KB	~3.5 MB (4x daha büyük)
RAM kullanımı	~50-100 MB	~200-400 MB
GPU kullanımı	Düşük-orta	Yüksek
İlk yüklenme süresi	1-2 saniye	4-8 saniye
Düşük-orta telefonda	✅ Akıcı	⚠️ Kasabilir, ısınabilir
Pil tüketimi	Normal	Yüksek
3D kalitesi	Binalar + eğim (yeterli)	Tam 3D dünya, arazi, uydu görüntüsü
“Ağır” = telefon daha çok çalışır, pil daha çok harcar, eski telefonlarda kasabilir.

Senin Projen İçin Hangisi Mantıklı?
MapLibre GL JS yeterli ve ideal çünkü:

Servis takip için kuş bakışı + hafif 3D eğim yeterli
Yolcular eski/ucuz telefonlardan da açabilmeli
Pil tasarrufu önemli (yolculuk boyunca açık kalacak)
Hızlı yüklenmeli (mobil veri ile)
CesiumJS ne zaman gerekir:

Google Earth gibi dünyayı döndürmek istersen
Uydu görüntüsü üzerinde 3D arazi istersen
Uçak/drone takibi gibi yükseklik önemli olan projeler
Kısa Özet:
MapLibre GL JS = Hafif, hızlı, ücretsiz, 3D binalar var, servis takip için mükemmel ✅
CesiumJS = Çok güçlü ama telefonu yorar, senin projen için gereksiz fazlalık ❌
MapLibre ile 3D eğimli, döndürülebilir, binaların göründüğü güzel bir harita yapabiliriz — CesiumJS’e gerek yok.

Harika Fikir! “Sanal Trafik Işığı” Mantığı 🚦
Senin önerdiğin mantık çok akıllıca — GPS hızına dayalı “sanal trafik ışığı” sistemi:

🧠 Senin Mantığın (Uygulanabilir!)
plain

Araç hızı 0-2 km/h + bilinen ışık noktasına &lt;100m mesafe
→ 🔴 KIRMIZI (duruyorsun, ışıkta bekliyorsun)

Araç hızı 2-10 km/h (yavaş hareket)
→ 🟡 SARI (kalkış/yavaşlama)

Araç hızı &gt;10 km/h
→ 🟢 YEŞİL (geçtin, yol açık)
Ekstra doğruluk için:

OSM’den bilinen ışık noktalarını al
Sadece o noktalara yakınken (100m) bu mantığı uygula
Açık yolda durma = trafik değil, yolcu indirme olabilir → durak yakınlığı kontrolü ekle
Haritada gösterim:

plain

🔴 Kırmızı ikon → &quot;Bu ışıkta bekleniyor&quot;
🟢 Yeşil ikon → &quot;Bu ışık geçildi&quot;
⚪ Gri ikon → &quot;Henüz varılmadı&quot;
Bu yolculara da gösterilebilir: “Şoför şu an 3. ışıkta bekliyor” gibi.

🌐 Google Canlı Trafik Nasıl Çalışıyor?
Google’ın sistemi çok farklı ve devasa bir altyapıya dayanıyor:

Kaynak	Nasıl?
Android telefonlar	Google Maps açık olan milyonlarca telefon anonim hız verisi gönderiyor
Waze kullanıcıları	Kullanıcılar kaza/trafik bildiriyor
Trafik sensörleri	Belediyelerle anlaşma — yol altındaki manyetik sensörler
Kameralar	Yapay zeka ile trafik yoğunluğu analizi
Geçmiş veri	“Her Pazartesi 08:00’da bu yol kırmızı” pattern’i
Kırmızı/yeşil ışık durumu için:

Google bazı şehirlerde belediye trafik kontrol merkezleriyle doğrudan bağlantı kurmuş
Ama çoğu yerde senin dediğin mantığın aynısını kullanıyor: “Bu noktada herkes duruyor → kırmızı olmalı”
Milyonlarca kullanıcının hız verisini birleştirerek tahmin ediyor
Yani senin mantığın aslında Google’ın temel mantığıyla aynı — tek fark Google milyonlarca araçtan veri topluyor, sen tek araçtan. Ama kendi servisin için gayet yeterli!

💡 Bizim Sistemde Ekstra Yapabileceğimiz
plain

1. Işık noktalarını OSM&#39;den çek (Ankara&#39;daki tüm ışıklar)
2. Güzergâh üzerindeki ışıkları filtrele
3. Şoför yaklaştığında hız bazlı durum belirle
4. Yolculara göster: &quot;2 ışık sonra durak&quot;
5. Geçmiş veri biriktir: &quot;Bu ışıkta ortalama 45 sn bekleniyor&quot;
   → ETA hesabına ekle!
Bu son madde çok değerli — zamanla ışık bekleme sürelerini öğrenip ETA’yı daha doğru hesaplayabiliriz.
